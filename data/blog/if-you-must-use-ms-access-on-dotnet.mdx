I'm working on migrating old codebase that was written on .NET Framework to a modern ASP.NET Core 8. One of the features we must persists is the ability to **generate an Access database** file (.mdb) exports. The old app was deployed on Windows machine, the new one **must work on Linux**. This is where I hit a roadblock when I found that the OleDb driver (driver to connect to Access databases) cannot ran on Linux, because the need of Windows COM component to run.

After doing some research online, there are few options that people suggested: 
1. Migrate to other database (pgsql, mysql etc,) 
2. Use [mdb-tools](https://github.com/mdbtools/mdbtools) 
3. Deploy a thin windows container app with the only purpose to do the export Access database thingy. The .NET app will trigger it via endpoint or command.
4. Use [UCanAccess](https://ucanaccess.sourceforge.net/site.html), which is a Java library that can read/write Access database files.

Well. I did try the options in order from top to bottom.

1. What? Nope! I **must use** Access.
2. Tested on Linux & Windows, it can read from Access, but **not writing** to it (bruh..)
3. Well this might works, but added complexity to maintain different apps and I need to rewrite the component from C# code to Java code.
4. This works! That's why I'm writing this whole blog post. Read along.

I actually have used **UCanAccess** previously, but not directly. UCanAccess is included in Dbeaver, the database management tool that I use. So before going any further I tested read & write capability of the driver on **both Windows & WSL**. It works like charm! Now, I **just** need to integrate it with my .NET app.

ucanaccess is a Java library, how do we even use it in .NET? **Meet [IKVM](https://www.ikvm.net/)**, a tool that allows you to translate Jar file to a .NET assembly (.dll).

First, you'll need to UCanAccess Jar files. You can get them from the [UCanAccess download page](https://sourceforge.net/projects/ucanaccess/files/) (Download the `*bin.zip`, not `*-src.zip`, ). The latest version as of writing is `5.0.1`. Read the steps below:

1. Extract the archieve.
2. Merge all the Jar files into one fat Jar file. Run `jar` in your terminal to see if you have JDK installed. If not, run the command below to install it.

    Debian/Ubuntu:

    ```bash
    sudo apt install default-jdk
    ```

    macos:

    ```bash
    brew install java
    echo 'export PATH="/opt/homebrew/opt/openjdk/bin:$PATH"' >> ~/.zshrc
    source ~/.zshrc
    ```

    Then, `cd` into the `UCanAccess-5.0.1.bin` folder, and run the command below to create 'fat' jar file.

    ```bash
    mkdir merged && cd merged && jar xf ../ucanaccess-5.0.1.jar && jar xf ../loader/ucanload.jar && for j in ../lib/*.jar; do jar xf "$j"; done && jar cf ../ucanaccess-all.jar . && cd .. && rm -rf merged
    ```

    This command will create a new file called `ucanaccess-all.jar` in the same folder. This file contains all the classes from the original UCanAccess Jar files.

Now on the .NET side. First, install [IKVM](https://www.nuget.org/packages/ikvm/) from Nuget. Put the file `ucanaccess-all.jar` somewhere in your project folder, then reference it in your `.csproj` file like below:

```xml
<ItemGroup>
  <IkvmReference Include="UCanAccessBin\UCanAccess-5.0.1.bin\ucanaccess-all.jar">
    <AssemblyName>ucanaccess</AssemblyName>
    <AssemblyVersion>5.0.1.0</AssemblyVersion>
    <AssemblyFileVersion>5.0.1.0</AssemblyFileVersion>
  </IkvmReference>
</ItemGroup>
```
When you build the project, IKVM will convert the the jar file into a `ucanaccess.dll` file in the output folder. You can then register this dll in your program.

Basic usage example to connect the database:

```csharp
// load ucanaccess dll
ikvm.runtime.Startup.addBootClassPathAssembly(System.Reflection.Assembly.Load("ucanaccess"));

// Load driver
java.lang.Class.forName("net.ucanaccess.jdbc.UcanaccessDriver");

// build the connection string
var accessPath = "/Users/fareez/Downloads/Access_sample.mdb";
var connectionString = $"jdbc:ucanaccess://{accessPath}";
var connection = java.sql.DriverManager.getConnection(connectionString);

// do something with the connection
// var statement = connection.createStatement();
```

That's all. **Please see [this repo](https://github.com/iqfareez/NetUCanAccessApp) for full code example, instructions and results**. It's a bit peculiar to see Java code inside .NET, but this the only way to interface with an Access database within .NET project. I hope this can help you if you are in the same situation as me.
